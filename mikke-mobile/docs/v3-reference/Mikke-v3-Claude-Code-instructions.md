## 1. 対象と正本

- 対象は**既存の Mikke モバイルアプリ**。過去の会話では Expo/React Native 系の開発が進んでいるが、ディレクトリ名、ライブラリ、現行スキーマはこの環境から参照できない。**必ず現行リポジトリを調べて確定**する。
- 見た目・ラベル・配置・画面遷移の正本は `Mikke-v3-reference.html`。この指示書は、どの動作を本物につなぐか、試作と製品の境界、受け入れ条件を補う。画面の細部に食い違いがあれば HTML と、最後のユーザー指示「最後の操作可能な画面を v3.0 とする」を優先する。
- HTML の写真4枚は参照用の埋め込み画像。サンプルの投稿、店舗名、件数、所要時間、予算、時刻、コメントは**実在データの保証がない**。製品データを偽装しない。
- 試作ではコンポーネントの状態は表示中だけのメモリー保存。実アプリではユーザーに紐づく項目を適切に永続化する。
- UI 以外で現在のアプリに実装済みの機能（SNS共有・URLからの抽出・保存・地図や位置情報・ログイン・プラン生成等）は現行仕様と後方互換を保つ。上書き・削除して画面だけ合わせない。

### 下部ナビゲーション

左から **ホーム / みんな / 中央の＋プラン / 保存 / マイページ** の5つ。中央だけ丸いグラデーションボタン。メニューはスクロール領域の下に固定し、長いコンテンツだけスクロールする。ホーム以外には上部に `Mikke` と地域を表示する。詳細画面は戻るで呼び出し元へ戻り、可能な場合は元画面のスクロール位置と検索状態を復元する。

### 検索・並び替えの厳密な挙動

- 検索欄は一行に収め、検索ボタンの隣に「詳細設定」。条件は初期状態で閉じる。並び順は詳細設定の外に常時表示。
- 絞り込みは地域・予算上限・系統（例：カフェ、ラーメン、自然）・テーマ（例：デート、ひとり）の AND 条件。キーワードはタイトル、地域、紹介、ジャンル、テーマ、立ち寄り先に当てる。
- 並び順はおすすめ、いいねが多い順、保存が多い順。件数・数値は権限とデータに整合した実数にする。データがないジャンルは正しい空状態を出す。
- カードは幅を伸ばした1列に切り替えず、狭いスマホでも2列に固定。文字や写真の切り詰め・タップ領域で読みやすさを守る。将来のタブレット表示は別設計でよい。

### 日記型のルート詳細

「みんな → 気になるルート → 一日の記録」の3段階で進める。**複数の立ち寄りを、一日の時系列で上から下に表示する**。各項目は「何時にどこへ行き、何をし、何を食べたか」等の小さな行動見出しと写真・短いコメントを持つ。立ち寄り間の移動表現は見た目を参照するが、実測していない時間・交通手段を確定値として示さない。

## 5. 試作と実アプリの境界

HTML の実装を読むとき、下表の左側は**仮の動き**とする。右側が v3.0 の実装上の目標。

| 試作の状態 | 実アプリで扱うこと |
| --- | --- |
| ルートは4件の固定サンプル | 実データの公開ルート一覧。無い場合は空状態/開発用シードを区別する |
| 「ルート生成」は決め打ち3案、経路・料金・営業時間を未計算 | 現行の `generate-plan` 等の実処理へ接続。提案の根拠や取得可否を確認し、未検証の時刻・費用は断言しない |
| 無料回数「残り3回」は固定 | 認証ユーザーの月次利用実績からサーバーを正本として算出。月替わりの基準時刻・対象操作は現在の料金仕様と整合するよう確認 |
| 投稿・写真・コメント・いいね・保存は画面内メモリー | ユーザーに紐づけて永続化。再起動・別端末・再ログインでも必要なデータが再現される |
| 画像は画面内の Data URI を表示 | 投稿写真を適切なストレージへ保存し、投稿/表示/削除のアクセス制御を確認 |
| 通知スイッチは表示だけ | 実通知の仕組みがある場合は購読/解除に結び付ける。無い場合は通知送信を実装済みと表示しない |
| URL登録フォームは URL と手入力場所名だけ | 既存の SNS 共有→URL/キャプション抽出→場所確認→保存の導線と統合する |
| 投稿公開はデモ内のみ | 明示的な公開確認、公開/非公開の取り扱い、本人のみ編集できる権限を実装 |

スキーマは**既存テーブルを起点**に判断する。過去の実装では `users / places / saved_places / plans / plan_items / visits` やプラン生成イベントがあるが、現在の DB と一致すると決めつけない。公開ルート、立ち寄り別写真/時刻/コメント、いいね、行きたい、コメント、通知設定などの不足分だけ、既存の命名規則と RLS に合わせて migration を用意する。公開投稿を取得する読み取りと本人の更新/削除を分ける。不要な重複テーブルを作らない。秘密情報を新たな UI コードや資料に転記しない。

**仕様未確定で進行を止めずに明示する項目**：実際の無料枠の上限とリセット境界、投稿写真の上限・圧縮・保持、公開投稿と「一覧から非表示」の違い、並び順の「おすすめ」の定義、通知の配信方式、対象地域の拡張。既存仕様があればそれを採用し、無ければ実装できる表示とデータ整合を先に作り、選択肢を報告する。

## 6. 推奨実装順と終了条件

1. **現状確認と保全**：作業ツリーの状態、構成、ルート、API、DB、既存動作を確認。未コミット変更は消さずに扱う。画面表と現在実装の差分を示す。
2. **共通 UI とナビ**：配色、文字、写真、5タブ、Safe Area、画面内スクロール、戻る導線を作る。ホームの完成イメージを基準に他画面を寄せる。
3. **閲覧と検索**：みんな2列・折りたたみ詳細設定・ソート・詳細日記型・いいね/行きたい/コメント。空状態/読み込み/エラーを含める。
4. **プランと記録**：既存生成処理に接続し、3ソース→条件→提案→選択→訪問→非公開保存を通す。架空のルートを実プランと混ぜない。
5. **投稿と保存**：立ち寄りごとの時刻・写真・ひと言、明示公開、4分類の保存一覧、自分の投稿を接続。
6. **マイページと設定**：実残り回数、表示名・地域、投稿表示、通知項目、ヘルプ、再起動後の永続化。
7. **実機 QA と差分修正**：Android を優先し、iOS の構成がある場合は両方確認。ナビ/スクロール/キーボード/写真許可/戻るボタン/ロード/空状態/通信失敗を確認し、参照 HTML と画面を見比べる。

**受け入れ条件**

- ホーム、みんな、＋、保存、マイページの各ボタンでページが開き、各ページをスクロールでき、下部ナビは残る。
- みんなのカードは常に2列。キーワード・詳細4条件・いいね順・保存順が画面と実データで一致する。
- みんなから選んだルートで、時刻・写真・ひと言付きの一日の記録が見られる。戻ると元の一覧へ戻る。
- プラン生成から記録、非公開保存、本人の明示操作で公開、自分の投稿および公開一覧への反映まで到達できる。
- マイページの残り回数は固定文字列でなく正しい利用実績に基づき、設定は再起動後も保存される。ただし既存仕様が未確定なら、未完成の数字を正確そうに表示せず、残作業を明示する。
- 既存の認証・共有取り込み・場所保存・位置情報・プラン生成/採用・訪問記録の主要導線が動く。
- 既存のチェックが通り、追加した重要なデータ処理には意義のある確認がある。実施していない実機や本番接続の試験を実施済みと書かない。

## 7. 参照 HTML 内で確認する場所

Claude Code が見た目と挙動を抽出するときの入口：

- CSS：`#mikke-demo` で始まるスタイル全体。色トークンは `.mikke-phone`、ホームは `.home-*`、検索は `.search-row` / `.filter-grid` / `.route-grid`、日記は `.story-*`、提案は `.result-*`、設定は `.settings-*` / `.setting-toggle`。
- 画面生成関数：`home`, `feed`, `detail`, `create`, `conditions`, `results`, `active`, `record`, `compose`, `share`, `saved`, `profile`, `settings`, `settingDetail`, `myPosts`。
- 遷移と操作：`render`, `tab`, `back`, `root.addEventListener('click'...)`, `root.addEventListener('change'...)`, `root.addEventListener('submit'...)`。
- デモ状態：`state`。4つの固定サンプルは `routes`。画像は HTML 内に埋め込み。`scrollPositions` は再描画後の位置復元例。
