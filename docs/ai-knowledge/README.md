## 1. このフォルダの使い方

1. 自分の役割を「4. 役割ごとの読み込みルール」で探し、●の文書を作業前に読む
2. 作業内容が○の文書の主題に触れるときは、その文書も読む
3. 文書同士が食い違って見えるときは「3. 優先順位」に従う。それでも決まらないときは人間に確認する
4. 「6. 未解決の要確認事項」に載っている論点は、**どちらかを自分で選ばず**、人間に確認する

## 2. 文書の区分

| 区分 | 意味 | AI社員の扱い |
|---|---|---|
| **POLICY** | 会社方針。原則として変えない | 従う。AI社員は変更してはならない（MUST NOT）。変更案は人間に提示する |
| **STRATEGY** | 現在の戦略。数週間〜数か月で変わりうる | 現時点の前提として使う。恒久的な事実として引用しない |
| **REFERENCE** | 料金・外部仕様など、時間で変わる情報 | **記載内容を事実として使わない。** 使う直前に公式情報を確認する |

### 重要度の表記（POLICY内）

| 表記 | 意味 |
|---|---|
| **【MUST】** | 必ず守る。例外は人間の承認が必要 |
| **【MUST NOT】** | してはならない。例外は人間の承認が必要 |
| **【SHOULD】** | 原則として守る。守らない場合は理由を記録する |
| **【MAY】** | してよい。判断は担当に任される |

### 確度の表記

| 表記 | 意味 |
|---|---|
| ［方針］ | 原文で採用すると明記されたこと |
| ［事実］ | リポジトリ内のファイル等で確認できたこと（根拠のパスを付ける） |
| ［仮説］ | まだ検証していないこと |
| ［TODO］ | 未決定・未実装。人間の決定または作業が必要 |

## 3. 優先順位

1. プロジェクト直下の `CLAUDE.md`（承認が必要な操作、作業ルール）
2. `01_COMPANY_CONSTITUTION.md`
3. その他の POLICY（02, 03, 04, 06, 07, 08）
4. STRATEGY（05, 09）、および `docs/ai-operations/strategy.md` `kpi.md`
5. REFERENCE（10）

下位の文書が上位と食い違う場合は上位に従い、食い違いを人間に報告する。

### 役割を追加するとき

1. 上の表に1行追加する（役割名、状態、●○）
2. 共通の3文書（01, 02, 09）は必ず●にする
3. 個人データ・DB・権限に触れる役割は 03 と 04 を●にする
4. 金額・外部サービスに触れる役割は 10 を●にする
5. `.claude/agents/<名前>.md` の「作業の進め方」に、読む文書の番号を書く（agent定義の変更は人間の承認後）

### 文書を追加するとき

- 連番を続ける（`11_...md`）。冒頭に区分・Version・最終更新・変更権限・関連文書・変更履歴を置く
- 4節の一覧と5節の表に列を足す
- 1つの文書に POLICY と REFERENCE を混ぜない
